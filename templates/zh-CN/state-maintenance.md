# 状态维护

规则只在 AGENTS.md 第 4 章维护。本页给条目模板和检查方法。

## 三层
| 层 | 文件 | 内容 |
|---|---|---|
| 根 | `STATE.md` | 只做导航；每轮读 |
| 模块 | `<模块>/STATE.md` | 每事项一条当前状态，链接详细正本；只读本轮涉及的模块 |
| 过程与历史 | 带日期的记录、`.space/history/` | 证据、旧正文、更正、失败；按需查 |

## 条目模板
```markdown
## 事项名称

- 现状（来源日期）：已经完成什么，实际验证到哪一层。
- 未决：仍缺什么；取消、暂停、未获批准的范围保留。
- 下一步：可接续的动作及触发条件，不把旧计划写成已执行。
- 依据：[详细正本](相对路径)、[本次记录](相对路径)。
```
同一事项的新状态替换这一条。旧正文存进带日期的记录，写明旧结论→新结论、来源日期和依据。其他事项保持不动，不要每次增加「本轮」段落。

## 一次任务怎样收尾
1. 写前重读目标；如果读取之后它变了，合并双方，不拿旧整文件回写。
2. 先保存将被替换条目的旧正文（`{{py}} .space/backup.py <文件>`），再保存新成果或证据。
3. 先更新详细正本，再更新模块 `STATE.md` 的条目。
4. 全文回读自己的改动：未决带过来没有、旧结论被清楚替代没有、链接能不能点开。
5. 只说验证过的。没重新核对的内容，写「沿既有记录」。

## 检查
```sh
{{py}} .space/state_check.py          # 大小、链接、日期标题、冲突副本、散落的 .bak
{{py}} .space/read_rules.py manifest  # 必读文件的大小和 SHA-256
{{py}} .space/record_check.py         # 项目文件夹有改动但「当前状态」没跟上
```
它们只读，也不能证明谁理解了规则。
